# 실제 AI Scanner 연동 체크리스트

## 1. 입력·출력 계약 확인

- [ ] 1차 스캔 함수 또는 명령의 정확한 호출 방식과 반환값을 확보한다.
- [ ] 재분석 전에 검토 의견과 증적을 전달하는 형식을 확보한다.
- [ ] `scan_id` 생성·조회 규칙과 완료/실패 상태값을 확인한다.
- [ ] 실제 결과 JSON 샘플에서 누락 가능 필드와 날짜·신뢰도 형식을 확인한다.
- [ ] 보고서 파일명과 생성 완료 판단 기준을 확인한다.

## 2. 어댑터 구현

- [ ] `adapters/tool_adapter.py`의 TODO만 실제 툴 호출로 교체한다.
- [ ] 호출 실패를 `ScannerAdapterError`의 안전한 메시지로 변환한다.
- [ ] API 키·인증 헤더·원문 응답에 포함된 비밀정보를 로그나 UI에 넣지 않는다.
- [ ] CLI 인자는 문자열 셸 명령으로 합치지 않고 안전한 인자 목록으로 전달한다.
- [ ] 타임아웃과 완료 상태 확인 방식을 명시한다.
- [ ] 실제 연결이 검증된 뒤에만 `is_live_connection = True`와 `AI Scanner 연결됨` 배지를 사용한다.

## 3. 정규화 매핑

- [ ] `normalizers/scanner_result_normalizer.py`에 실제 키 별칭을 추가한다.
- [ ] 취약점 유형을 고정 목록으로 제한하지 않는다.
- [ ] 신뢰도가 0~1인지 0~100인지 확인한다.
- [ ] 초기 위험도와 최종 위험도를 서로 다른 필드로 보존한다.
- [ ] 증적을 `finding_id`와 연결한다.
- [ ] 알 수 없는 값과 누락 값으로 대시보드가 중단되지 않는지 확인한다.

## 4. 파일·보고서 안전성

- [ ] 결과 읽기 경로가 허용된 results 루트 내부인지 검증한다.
- [ ] 원본 `active-scan-*` 폴더를 대시보드가 수정하지 않는지 확인한다.
- [ ] 세 PDF가 실제로 존재할 때만 다운로드를 제공한다.
- [ ] 파일의 전체 로컬 경로를 UI에 표시하지 않는다.
- [ ] 업로드 파일을 실행하지 않고 크기·확장자·JSON 문법만 검사한다.

## 5. 통합 검증

- [ ] mock 모드의 1차 버튼과 재분석 버튼이 계속 동작한다.
- [ ] 실제 1차 결과가 표준 `ScanResult`로 표시된다.
- [ ] 검토 메모와 증적이 실제 재분석 입력에 전달된다.
- [ ] 재분석 결과에 최종 위험도·오탐 판정·보고서가 반영된다.
- [ ] 미설정 CLI/REST가 명령이나 네트워크 요청 없이 안내 오류만 반환한다.
- [ ] 취약 웹 서버 파일과 DB에 변경이 없는지 확인한다.
